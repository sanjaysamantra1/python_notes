REST ARCHITECTURE
-----------------
-REST = Representational State Transfer
-Stateless communication: The server does not remember any information about previous requests.
-Each request contains all required information: Since REST is stateless, every request must contain all data needed for processing
-Resource-based URLs: Resources are identified using URLs

Examples:
GET      /users
GET      /users/1
POST     /users
PUT      /users/1   
PATCH    /users/1
DELETE   /users/1
HEAD     /users
OPTIONS  /users



-HTTP is a Protocol, HTTP provides the rules for client-server communication
-HTTP defines things such as:
	Request structure
	Response structure
	HTTP methods
	Headers
	Status codes
	Request body
	Response body
	Caching behavior
	Authentication mechanisms
	Content types



HTTP Methods
============
GET - Fetch Data from the server (ex: search products)
      Doesn't change Data
	  Safe, Idempotent, No Request Body
	  
POST - Send Data to create a new resource( sign up )
	   while fetching the Data if client wants to send parameters in Request body not in Request URL
	   Not Idempotent, Request Body

PUT - Replace an existing resource completely
      Idempotent, Full Update , Complete Object in Request Body
	    
PATCH - Update only specific fields of a resource
		update password/mobile 
		Idempotent, Partial Update , More Efficient than PUT, Request Body

DELETE - remove a resource/delete a record from DataBase
		 Delete an account
		 Idempotent, No Body
		 
HEAD - Get Headers only	, Same as GET but no response body
       Used For Checking existance, performance checks
	   
OPTIONS - Returns Supported HTTP Methods
          Used in CORS
          Browser preflight requests		  
		 




Idempotent
----------
-An HTTP method is idempotent if making the same request multiple times results in the same server state.
-The response may be same or different, but the data on the server doesnt change after the first request.
-POST is non-idempotent, Whereas GET,PUT,PATCH,DELETE are idempotent

POST   api/users
{'name':'sanjay','address':'Bangalore'}
1st request --> User Created ( id=10 )
2nd request --> User Created ( id=11 )
3rd request --> another User Created ( id=12 )
-Database state changes every time, POST is non-idempotent


PUT  api/users/1 
{'name':'sanjay','address':'Bangalore'}
1st request --> user becomes  (Sanjay,Bangalore)
2nd request --> user is still  (Sanjay,Bangalore)
10th request --> user is still  (Sanjay,Bangalore)
-DataBase state stays the same, PUT is idempotent



PUT vs POST
-----------
-PUT for UPDATE operations, POST for CREATE operations.
-PUT is idempotent, where POST is non-idempotent.
-Use PUT when you want to modify a singular resource which is already a part of resources collection.
-Use POST when you want to add a child resource under resources collection.


PUT vs PATCH
------------
-PUT is used to replace a complete resource.
-PATCH is used to apply partial modifications to a resource.

JSON
======
-JavaScript Object Notation
-JSON is a text-based data interchange format used to exchange data between client & server.
-Uses key-value pairs. Key/value separated by :
-Keys must be strings
-Keys use double quotes
-Multiple properties separated by ,
-No trailing comma
-No comments


Why JSON:
-Without a standard format, different systems could represent data differently
-JavaScript object, Python Dictionary , Java object, Database record
-JSON provides a common representation
-Human readable
-Language-independent

Example:
{
  "id": 101,
  "name": "John",
  "email": "john@example.com",
  "is_active": true
}



Serialization : Converting Python object → JSON
Deserialization : JSON → Python object

import json
user = {"id": 101,"name": "John"}
json_data = json.dumps(user)
print(json_data)
print(type(json_data))

json_data = '{"id": 101, "name": "John"}'
user = json.loads(json_data)
print(user)
print(type(user))





FastAPI Benefits
================
-High Performance : 
	-FastAPI is built on top of Starlette, an ASGI-based web framework, which allows FastAPI to handle asynchronous requests efficiently
	-while the request is waiting for an I/O operation, the server can work on other requests instead of blocking the thread

-Easy to Learn : 
	-FastAPI uses normal Python concepts rather than introducing a completely different programming model
	
-Type Hint Support : 
	-specify expected types : Request validation, Response validation
	
-Automatic Validation :
	-FastAPI integrates with Pydantic to validate incoming data
	
-Automatic API Documentation :
	-FastAPI automatically generates interactive API documentation.
	
-Async Support : 
	-supports asynchronous programming model (async, await)
	
-OpenAPI Standard : 
	-OpenAPI is a standard for describing HTTP APIs.  API documentation

UVICORN
=======
-Uvicorn is a web server used to run FastAPI applications.
-Uvicorn acts as the driver that starts and runs the FastAPI application.
-FastAPI only defines API routes and business logic.
-It does not listen for HTTP requests by itself.
    A web server is required to:
    -Start the application
    -Listen on a port
    -Accept requests
    -Send responses
-Uvicorn performs all these above tasks.

Routing in FastAPI
=================
-Routing is the process of mapping an HTTP request to a specific Python function.
-FastAPI provides decorators for different HTTP methods.
-A FastAPI application can have many routes.

GET Route:
	@app.get("/users")

POST Route:
	@app.post("/users")

PUT Route:
	@app.put("/users/{id}")

DELETE Route:
	@app.delete("/users/{id}")




Path Parameters
===============
-A path parameter is a variable value embedded directly into the URL path.
-Used to pass values through URL. defined using {}
-FastAPI supports Path Parameter with Type Hint, when not followed FastAPI automatically returns a validation error.

@app.get("/users/{user_id}")
def get_user(user_id:int):  #user_id must be an integer
    return {
        "user_id": user_id
    }

Request: http://localhost:8000/users/101


Multiple Path Parameters:
@app.get("/users/{user_id}/orders/{order_id}")
def get_order(user_id: int, order_id: int):
    return {
        "user_id": user_id,
        "order_id": order_id
    }




Query Parameters
================
-A query parameter comes after ? in the URL.
-Used for filtering and pagination.
	ex: GET /products?category=electronics
-Query parameters are separated by & 
  /products?category=electronics&min_price=10000&max_price=50000
-By default, query parameters are required. FastAPI returns a validation error when Query Parameter is not provided
-Optional Query Parameters: Use a default value
 def get_products(category: str | None = None):
 

Example:
@app.get("/users")
def get_users(page:int=1,size:int=10):
    return {"page":page,"size":size}

URL:
http://localhost:8000/users?page=1&size=10







Request Body
============
-Data Sent from client to server with POST, PUT, PATCH requests.
-We Describe the shape of Request Body with a pydantic model
-FastAPI then parses, validates, converts and documents it automatically


Example:
from pydantic import BaseModel

class User(BaseModel):
    name:str  		# required field
    age:int   		# required field
	address:str | None = None  #optional field

@app.post("/users")
def create_user(user:User):
    return user


-For stricter input, use validation rules

 from pydantic import BaseModel, Field, EmailStr
 class User(BaseModel):
    name:str = Field(min_length=2, max_length=100)		
    email:EmailStr
    age:int = Field(ge=18,le=100)	
	address:str | None = None

Dependency Injection
====================
-A dependency is reusable logic that a route needs, and FastAPI automatically executes and provides its result.

Example:
from fastapi import Depends
def common():
    return "dependency"

@app.get("/")
def home(data=Depends(common)):
    return data

Benefits:
-Reusable Code
-Clean Architecture
-Loose Coupling






HEADERS
=======
-Headers contain metadata about the HTTP request.

from fastapi import FastAPI, Header, Response
app = FastAPI()
@app.get("/hello")
async def hello(
    response: Response,
    authorization: str | None = Header(default=None),
    x_request_id: str | None = Header(default=None),
):
    # Request headers received from the client
    print("Authorization:", authorization)
    print("X-Request-ID:", x_request_id)

    # Response headers sent back to the client
    response.headers["X-Response-ID"] = "response-123"
    response.headers["X-Custom-Header"] = "hello"

    return {
        "message": "Hello",
        "received_headers": {
            "authorization": authorization,
            "x_request_id": x_request_id,
        },
    }
